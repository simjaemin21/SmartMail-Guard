SmartMail Guard 2.0을 skill-to-service 스킬로 외부 공개 체험 웹서비스로 전환하고 싶습니다. 기존 smartmail-guard-email-triage-v2 스킬을 사용하세요.

[대회 필수] 개발 플랫폼 Timely AI, LLM은 Solar Pro 4만 허용됩니다. 다른 LLM(Gemini, GPT, Claude 등)은 사용하지 마세요. 기존 GitHub 코드를 임의로 덮어쓰지 마세요.

[기능 범위] P0는 ① 이메일 보안 분류 ② 중요도/보안 대응 우선순위 분리 ③ 원문에 근거한 일정·기한 표시 ④ 안전 행동 카드 입니다. P1은 상세 근거·경고·결과 내보내기 입니다. 실제 Gmail 연동, 메일 삭제/답장, SPF/DKIM 검사, 악성 링크 탐색, 캘린더 자동 등록은 구현된 척하지 마세요.

[아키텍처] 먼저 스킬을 바탕으로 PRD 11항목(한 줄 정의, 타깃 사용자, 문제, 트리거, 핵심 기능, 스킬 매핑, 입출력, 필요 설정, 데이터 규칙, 성공 기준, 제외 범위)을 작성하세요. 저장소 구조 및 배포 계획을 보여준 다음 구현하세요.

[LLM/API 정직성] 외부 공개 웹사이트에서 실시간 Solar Pro 4 호출이 가능한 **공식 인증 방식이 실제 확인된 경우에만** API 모드를 구현하세요. 외부 API 사용권이 없으면 웹에는 '규칙 기반 체험 (LLM 아님)' 또는 '미리 분석된 예시 결과'로 명확히 표시하고, 실제 Solar Pro 4는 Timely 내부 에이전트에서 시연할 계획입니다. 규칙 기반 결과를 Solar 분석으로 표기하지 마세요. 실시간 호출 실패 시 다른 모델이나 가짜 결과로 자동 대체하지 마세요.

[배포] Timely의 Vercel 커넥터가 연결되어 있으면 배포를 시도하세요. 액세스 토큰, API 키를 코드에 기록하거나 채팅에 노출하지 마세요. 실제 배포 후 incognito 접속, P0의 4개 기능, 모바일 화면, 비용 제한을 검증하고 실제 생성된 URL만 보고하세요. Vercel이 불필요하면 기존 Streamlit 공개 앱을 유지해도 됩니다.
