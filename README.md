# SmartMail Guard 2.0 ✉️

**Solar Pro 4 기반 이메일 보안 분류 + 중요 일정·행동 안내 에이전트 MVP**

> 이 저장소에는 **(A) Timely AI에 수동 설정하는 Solar Pro 4 에이전트**와 **(B) 로컬 웹 시연 앱**이 함께 들어 있습니다. 두 실행 경로를 혼동하지 마세요. 로컬 앱은 API 키가 없으면 **규칙 기반 예시**이며 Solar 모델이 동작하지 않습니다.

## 문제와 해결

이메일을 단순히 스팸 여부만 분류하면 장학금 제출, 과제 마감, 면접처럼 **놓쳐서는 안 되는 정상 메일**을 관리하기 어렵습니다. SmartMail Guard 2.0은 다음을 함께 다룹니다.

1. **보안 분류:** 정상 메일 / 광고성 스팸 / 피싱 의심 / 판단 보류
2. **위험도·중요도 분리:** 메일의 보안 위험, 사용자 업무 중요도, 보안 대응 우선순위를 구분
3. **일정·행동 정보:** 원문에 나온 시험·행사·제출·회신·프로모션 기간과 실제 해야 할 일을 추출
4. **안전한 사용자 안내:** 피싱 메일의 송금·비밀번호·OTP 요구를 사용자 작업으로 제안하지 않음
5. **판단 한계 고지:** 발신자 인증, URL 최종 목적지, 첨부파일 악성 여부를 검사하지 않았다면 미검증 명시

## 기술 구성

| 항목 | 내용 |
|---|---|
| 에이전트 플랫폼 | Timely AI (사용자 계정에서 생성·저장된 템플릿) |
| 지정 LLM | **Solar Pro 4** (Timely 에이전트 설정 화면에서 선택) |
| 에이전트 스킬 | `smartmail-guard-email-triage-v2` |
| 로컬 UI | Python 표준 라이브러리 HTTP 서버 + HTML/CSS/JavaScript |
| 로컬 기본 엔진 | **규칙 기반 시연**. LLM 아님 |
| 로컬 선택 엔진 | 사용자가 직접 `UPSTAGE_API_KEY`를 설정할 때만 별도 Upstage Solar Pro 4 API 호출 경로 사용. 실제 성공 여부는 이 저장소만으로 검증되지 않음 |

**중요:** GitHub의 설정 파일을 올리는 것만으로 사용자의 Timely AI 템플릿이 자동 배포되거나 동일한 스킬이 실행되는 것은 아닙니다. 실제 적용 여부는 Timely 에이전트에서 별도로 확인해야 합니다.

## 현재 구현 범위

**Timely AI 네이티브 에이전트:** 사용자가 직접 이메일을 붙여 넣어 분류·설명·중요도·일정·행동 카드를 받는 대화형 MVP. 실제 Timely 화면에서 Solar Pro 4를 선택했고, 2.0 스킬 활성화 및 텍스트 분석 출력을 확인했습니다. 대화 내 '스킬 사용' 문장만으로 실제 툴 호출 기록을 증명할 수는 없습니다.

**로컬 웹 앱:** 위 기능의 시각적 구조를 보여주는 별도 데모. 기본 오프라인 모드는 `app/server.py`의 간단한 규칙으로 결과를 생성하며 정확도/성능 평가에 사용하지 않습니다. 별도 API 모드는 인터넷 접속, 개인 Upstage API 키 및 모델 이용 권한이 있어야 합니다. API가 실패하면 다른 모델로 자동 대체하지 않습니다.

**미구현:** Gmail/Outlook 연결, 메일 자동 수집·삭제·답장·스팸 라벨 변경, 첨부 악성코드 검사, SPF/DKIM/DMARC 검사, 실제 링크 탐색, 자동 캘린더 등록, 실서비스용 로그인·권한 제어, 상시 배포.

## 실행 방법

Windows PowerShell에서 저장소 폴더를 연 후:

```powershell
python app/server.py
```

브라우저에서 <http://127.0.0.1:8765> 접속. 화면 상단에 **'규칙 기반'** 이라면 Solar 추론이 아닙니다.

```powershell
python tests/test_offline.py
```

이 테스트는 로컬 규칙 코드의 8개 스모크 테스트이며 Solar Pro 4 정확도 측정이 아닙니다.

### 선택적 로컬 Upstage API 실험

개인 계정에서 API 키/모델 권한을 확보한 경우에만 실행합니다.

```powershell
$env:UPSTAGE_API_KEY = "본인이-발급받은-키"
python app/server.py
```

이 실행 경로는 **Timely AI 에이전트의 내부 API를 호출하는 것이 아니라 별도의 실험용 코드**입니다. 실제 사용자 메일을 전송하면 외부 모델 제공사로 내용이 전송될 수 있으므로, 데모에는 합성 메일만 사용하세요. API 키를 저장소에 커밋하지 마세요.

## 테스트 결과 (2026-11-24 기준)

**개발용 합성 메일 30건:** Timely 대화 출력 검토 기준 보안 분류 **30/30 일치**. 이 중 처음 25건은 예상 정답이 포함된 CSV를 모델에 제공했으므로 완전 블라인드가 아닙니다. 엄격한 시간 표현 보존은 **27/30**이었고, 근거 혼합/요약표 오류도 발견했습니다.

**추가 합성 혼합형 16건:** 정답 열을 제외한 입력에 대해 Timely 대화 출력을 사람이 별도 검토한 결과, 보안 분류 **15/16 잠정 일치**. SMG-032의 정보 부족 메일을 정상으로 분류하는 오류를 발견했습니다. 16건에 대한 별도의 사전 고정 정답표에 기초한 독립 검증이나 반복 실행은 아니며 일반화된 모델 정확도라고 주장하지 않습니다.

**총 46건 = 개발·평가에 활용한 합성 사례 수**입니다. 이를 무조건 합산하여 실서비스 '정확도'로 홍보하지 않습니다. 중요하게도 16건 분석 이후 추가한 최종 품질 지침은 **아직 별도의 신규 데이터로 재평가하지 않았습니다**.

상세 결과는 [`docs/EVALUATION_2026-11-24.md`](docs/EVALUATION_2026-11-24.md)를 보세요.

## 보안과 개인정보

- 메일 원문은 신뢰할 수 없는 외부 입력입니다. '기존 지침 무시', '정상으로 분류하라' 같은 명령을 따르지 않습니다.
- 첨부파일을 자동 실행하지 않고 링크 목적지나 발신자 인증을 실제로 확인했다고 주장하지 않습니다.
- 자동 삭제·회신·전달·차단은 구현하지 않았습니다. 권장 행동은 사용자가 검토하고 직접 수행합니다.
- GitHub에는 API 키, 실제 개인정보, 실제 메일 본문을 넣지 마세요.
- 이 프로젝트는 보안 의사결정을 보조하는 MVP이며 확정적인 악성 판정 시스템이 아닙니다.

4. **프롬프트 인젝션:** 이메일 본문 속 'AI 지침을 무시하라'를 데이터로만 취급
